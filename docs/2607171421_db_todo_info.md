**Recommendation:** Use `TIMESTAMPTZ` (`TIMESTAMP WITH TIME ZONE`). PostgreSQL stores it as UTC internally, displays it in the session timezone.
```sql
-- Example migration approach (per table):
ALTER TABLE kbase.sections
  ALTER COLUMN date_created TYPE timestamptz USING date_created AT TIME ZONE 'UTC',
  ALTER COLUMN date_modified TYPE timestamptz USING date_modified AT TIME ZONE 'UTC',
  ALTER COLUMN date_modified_info TYPE timestamptz USING date_modified_info AT TIME ZONE 'UTC';
-- ... (repeat for all tables)
```

### 7. `show_level` — вузьке рішення для прав доступу

Поле `show_level int` (0=приватний, 1=зареєстровані, 2=публічний) є простим, але не масштабованим. У проекті вже є таблиці `roles` і `privileges`.

**Рекомендація:** Розглянути зв'язок між `sections` та `roles`:
```sql
kbase.section_access  -- таблиця прав доступу до розділів
    section_id bigint,
    role_id bigint,
    access_level smallint  -- 1=read, 2=write, 3=delete
```
Або залишити `show_level` як "базовий рівень" і додати більш гранульовані права пізніше — це також прийнятне рішення для MVP.
